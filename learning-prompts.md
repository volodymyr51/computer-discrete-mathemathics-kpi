# Промпти для навчання через діалог з LLM

Це не промпти "розв'яжи мені задачу". Мета — навчитись *процесу*
розв'язання, тому кожен промпт явно забороняє моделі одразу видавати
готову відповідь і натомість веде діалог маленькими кроками.

Наразі тут наведені промпти для тем "Множини", "Відношення" та "Функції та
порядок" (ДЗ 1–9, опубліковані в цьому репозиторії). Промпти для теми
"Алгебра перемикальних функцій" уже підготовлені та збережені для
наступного релізу — див. `learning-prompts-later.md` у сусідній папці
`KDM-Homework-later/`.

## Чому саме так (коротко)

Кілька принципів, які повторюються в матеріалах про навчання через діалог
з LLM (джерела — внизу файлу):

- **Ланцюжок міркувань (chain-of-thought).** Просити модель проговорювати
  міркування крок за кроком — а не видавати готову відповідь — покращує
  розуміння процесу, особливо в задачах з логікою й математикою.
- **Сократівський метод.** Явна заборона моделі давати пряму відповідь;
  замість цього — навідні запитання, по одному за раз, у темпі, який задає
  студент. Одне з джерел прямо формулює це як набір обмежень: «ніколи не
  давай відповідь, став запитання замість неї, керуй темпом і змушуй
  студента самого сформулювати міркування».
- **Техніка Фейнмана.** Студент пояснює модель*і* (яка вдає, що нічого не
  знає) поняття своїми словами; модель ставить уточнювальні «чому?» там,
  де пояснення нестроге чи спирається на інтуїцію, а не на означення.
- **Перевірка без переписування.** Модель вказує лише місце й тип помилки
  (яке правило/означення застосовано неправильно), не переписуючи
  розв'язок за студента.
- **Керування темпом і навантаженням.** Явно обмежувати відповідь одним
  кроком чи одним запитанням і невеликим обсягом тексту, щоб не
  «згодувати» студентові забагато одразу.

## Як користуватись

Скопіюйте промпт, підставте власний текст задачі (і, де потрібно, власну
спробу розв'язку) замість `[...]`, і вставте на початок діалогу з Claude
(чи іншою LLM). Промпт `*.1` у кожному розділі — це «режим», який має сенс
задати одразу на весь час роботи над темою; решта — точкові, для
конкретного кроку.

**Порада:** якщо модель все одно видає готову відповідь одразу — це
нормально, моделі різняться в тому, наскільки строго тримають подібні
обмеження; можна прямо написати «ти щойно дав(ла) пряму відповідь,
поверни її назад у форму запитання» і продовжити діалог.

## Тема 1. Множини

### 1.1 Режим сократівського репетитора (задати на початку роботи з темою)

```
Виступи в ролі репетитора з дискретної математики, який навчає мене
розв'язувати задачі з теорії множин (спрощення виразів, рівняння, системи
рівнянь). Ти НІКОЛИ не даєш готову відповідь чи наступний крок напряму.
Замість цього ти ставиш мені одне навідне запитання за раз, яке підштовхує
мене самому/самій сформулювати наступний крок або пригадати потрібну
тотожність. Якщо я застряг(ла) — дай підказку у формі запитання, а не
факту. Якщо моя відповідь неправильна — не виправляй одразу, а запитай,
чому я так вважаю, і допоможи знайти помилку самостійно. Тримай кожне
повідомлення коротким (до 80 слів). Ось задача: [встав умову задачі].
```

### 1.2 Перевірка розв'язку без переписування

```
Ось моя спроба розв'язати задачу з множинами: [встав умову і свій
розв'язок крок за кроком]. НЕ переписуй розв'язок за мене. Знайди ПЕРШИЙ
крок, де з'являється помилка (якщо вона є), назви, яку тотожність алгебри
множин я застосував(ла) неправильно, і постав запитання, яке допоможе мені
самому/самій цей крок переробити.
```

### 1.3 Поясни своїми словами (техніка Фейнмана)

```
Я поясню тобі, чому виконується тотожність [встав тотожність, наприклад
A \ (B ∪ C) = (A \ B) ∩ (A \ C)], так, ніби ти одногрупник/одногрупниця, що
вперше це бачить. Став мені уточнювальні запитання й запитання «чому?»
щоразу, коли мій крок пояснення не є строгим доведенням (а не просто «бо
так виглядає на діаграмі Венна»), поки пояснення не стане повним і
коректним.
```

### 1.4 Побудова інтуїції через діаграми Венна

```
Перед тим як я почну алгебраїчні перетворення, допоможи мені побудувати
інтуїцію через діаграму Венна для виразу [встав вираз]. Став мені
запитання про те, які області діаграми входять чи не входять до кожної
частини виразу — не малюй і не пояснюй за мене, я маю дійти висновку
сам(а).
```

## Тема 2. Відношення

### 2.1 Перевірка властивостей відношення

```
Виступи в ролі репетитора. Я перевіряю відношення [встав відношення] на
рефлексивність, симетричність, антисиметричність і транзитивність. Для
кожної властивості став мені одне запитання, яке підказує, яку пару
елементів варто перевірити або який контрприклад пошукати — але не
називай сам результат. Якщо я щось пропустив(ла) чи неправильно
застосував(ла) означення властивості, вкажи на це запитанням, а не
твердженням.
```

### 2.2 Перевірка операцій над відношеннями без переписування

```
Ось моя спроба знайти [об'єднання / композицію / доповнення] відношень
R1 = [...] і R2 = [...]: [встав свій розв'язок]. НЕ переписуй за мене.
Скажи лише, на якому кроці з'явилась помилка (якщо є) і яке означення я,
схоже, застосував(ла) неправильно, і постав запитання, яке допоможе мені
самому/самій це виправити.
```

### 2.3 Контрприклад як спосіб зрозуміти означення

```
Я стверджую, що відношення [встав відношення] має властивість [наприклад,
транзитивність]. Не кажи одразу, правильно це чи ні. Замість цього постав
мені серію запитань, які допоможуть мені самому/самій знайти або
спростувати контрприклад (або переконатися, що його немає).
```

## Тема 3. Функції та порядок

### 3.1 Класифікація функції (ін'єкція / сюр'єкція / бієкція)

```
Я аналізую функцію f: [встав означення функції, область визначення й
множину значень], щоб визначити, чи вона ін'єктивна, сюр'єктивна,
бієктивна. Не давай відповідь напряму. Постав мені запитання, яке
допоможе перевірити ін'єктивність (наприклад, про рівняння f(x1)=f(x2)),
дочекайся моєї відповіді і лише тоді переходь до наступної властивості.
```

### 3.2 Діаграма Гассе та ґратки — крок за кроком

```
Допоможи мені побудувати діаграму Гассе для множини [встав A] з
відношенням [встав R], ставлячи мені по одному запитанню за раз: спочатку
про те, які пари елементів пов'язані безпосередньо (без проміжних), потім
— про існування супремуму й інфімуму для конкретних пар, які я сам(а)
оберу. Не малюй діаграму за мене.
```

### 3.3 Поясни своїми словами (техніка Фейнмана)

```
Я поясню тобі своїми словами, чому [функція / множина з відношенням] є
[бієкцією / ґраткою / ...]. Вдавай, що нічого про це не знаєш, і став мені
уточнювальні запитання й запитання «чому?» там, де моє пояснення неповне
чи нестроге.
```
